# DeepSeek Harness 功能支持盘点

状态：2026-10-04，按 omdsh 当前工作区与 DSH `dsh-v0.2.1-alpha.1` 核对。此文件记录功能覆盖与接入条件，已实现项单独标记，不替代真实平台与环境验收。当前依赖基线见 [DeepSeek Harness 集成与兼容](deepseek-harness.md)。

统计单位是用户能力而不是 npm 包数。一个能力可能由 service、provider、tool 和 UI 多个包组成；已经有一个可用 provider 时，不因没有安装所有替代 provider 而记为整项缺失。产品支持自定义 Profile 与插件组合，因此“未产品化”表示缺少随产品交付、配置、展示和验证的完整路径，不表示底层完全无法挂载。

## 统计结论

| 范围 | 数量 | 口径 |
| --- | --- | --- |
| 核心交互与运行时 | 11 项跟踪，1 项未接入、1 项部分支持 | C01–C04、C07–C11 已实现对应产品入口；C06 提供行输入控制台，原始 PTY 附着未实现；Windows 仍待实机验收 |
| 可选或实验扩展 | 20 组 | 部分已有通用 MCP、Skill 或 provider seam，但缺少对应官方能力的配置、交互与真实环境验证 |
| 独立宿主模式 | 4 组 | SDK、ACP server、Web/Desktop 与浏览器 Worker，需要独立入口和生命周期 |
| 同能力替代 provider | 1 组 | Search、Storage、Title 已有实现，不计为整项缺失 |

初始盘点的 35 个能力组不是 35 个 bug，也不等同于 35 个包；其中九项已完成对应产品入口，持久终端提供行输入控制台。若“全部支持”指上游所有可交付能力，应分别验收默认核心功能、按需启用的扩展和独立宿主；不能将互斥 provider、实验权限模式或外发日志全部默认启用。这个盘点没有给覆盖率百分比：上游包粒度不同，且真实平台/外部环境尚未逐一验收。
