# 引导运行中的任务

读完本教程，你可以排队后续消息、进入 Plan mode，并查看任务进度。

### 排队或插话

Agent 正在检查项目时，可以尝试下面一种操作。输入区上方的投递标签会告诉你消息将在什么时候生效。

| 你想做什么 | 操作 | 预期结果 |
|---|---|---|
| 当前任务结束后追问 | 输入“接下来总结一下测试配置”，按 `Alt+Enter`。 | 出现 **排队 · 下一回合**，等待当前回合完成。 |
| 纠正当前任务 | 输入“先关注启动路径”，按 `Alt+S`。 | 出现 **插话 · 下一步**。当前工具调用结束后，Harness 会在下一个模型步骤前投递。 |
| 修改最新的排队请求 | 输入区为空时按 `Alt+Up`，修改后重新提交。 | 消息回到输入区，供你编辑。 |
| 管理多条待处理请求 | 打开 `/queue` 或按 `Alt+Q`。 | 选择一条消息，编辑、撤回或调整顺序。 |

默认情况下，运行中按 Enter 也会排队。**设置 → 终端 → 输入 → 运行时 Enter 行为** 可以把它改为插话。显式的 `Alt+Enter` 和 `Alt+S` 含义固定，两者都支持随文字提交图片和文件。

中断任务可以按 `Esc`，或在空输入区按 `Ctrl+C`。退出时间窗口内再次按 Ctrl+C 会离开 omdsh。会话仍挂载时，已接收的待处理消息继续保留；正常退出和切换会话的清理会清空 Harness 队列。重启后恢复的本地输入需要先审核再发送。完整的编辑、中断和恢复规则见[会话与历史](../sessions.md#待处理消息与恢复)。

### 修改文件前先制定计划

对于需要先调查再提出实现方案的任务，运行 `/plan`。Plan mode 会指导模型先进行只读检查，再通过审批流程提交可审阅的计划。

- `/plan <message>` 在进入 Plan mode 的同时发送第一条规划要求。
- `/plan off` 直接退出 Plan mode。

计划审核出现后，先阅读方案，选择 **Approve** 继续实施，或选择 **Keep planning** 提供修改意见。整个流程中的工具权限由 Access 控制，审核操作详见[命令](../commands.md)。

Composer 中的图片和文件会随支持附件的 `/plan` 和 `/goal` 请求提交。`/plan off` 等不接受附件的子命令会恢复完整草稿，供修改后重新发送。

### 跟踪任务进度

当 Agent 写入 Todo 列表后，Composer 和队列上方会出现紧凑的任务树，分别表示已完成、当前和待处理工作。任务树就是列表本身，不再提供把已过时副本打印进 Transcript 的命令。

Todo 描述当前回合的工作，而 `/goal <objective>` 用于控制更长时间运行的目标。不带参数运行 `/goal` 可以查看当前状态和可用操作。被委派的子代理会出现在 composer 上方的 roster 中，按 `↓` 选中、`Enter` 打开其转录；[子智能体与委派](../subagents.md)介绍了三种 transport 以及如何引导可继续的孩子。
