# 管理长会话与安全回退

真实项目里，一个需求往往横跨好几天、几十个回合，中间还可能试错走弯路。这篇教程帮你把“找回旧对话、退回重试、撤销改乱的文件、给长对话瘦身”四件事彻底串起来。

## 一、恢复并整理历史会话（`/resume`）

无论你是刚重启终端，还是想接着昨天做到一半的任务继续：

- **命令行直接续接**：退出 omdsh 时终端会打印一行 `omdsh --resume <会话ID>`，直接粘贴即可原样回到那次对话；
- **界面内搜索恢复**：进入 omdsh 后运行 `/resume`（或直接输入 `/resume 关键词` 进行全文搜索），按标题、时间和内容筛选后按 `Enter` 切换。

> **常见踩坑：为什么 `/resume` 找不到昨天的会话？** `/resume` 默认只列出**当前工作目录**关联的会话。如果你换到了上一级目录或另一个工作目录，列表里就不会显示昨天的会话——切回原目录启动，或在命令行用 `omdsh --resume <会话ID>` 直接指定即可。

在 `/resume` 列表里，还可以顺手整理常用会话：

- **`Alt+P`**：置顶/取消置顶重要会话；
- **`Alt+R`**：给会话重命名（例如改成“订单导出重构”），比自动生成的标题更好找；
- **`Alt+A` / `Alt+V`**：归档已结束的旧会话，或切换查看归档列表；
- **`/name <新名称>`**：在对话中直接修改当前会话的标题。

## 二、走弯路时：用会话树开分支（双按 `Esc`）

假如你在第 3 轮试了一套方案，改到第 7 轮发现思路不对，想回到第 3 轮换另一种做法，但又不想丢掉刚才的排查记录——这时用 **会话树（Session Tree）**：

1. 在空输入框下**连续按两次 `Esc`**，打开当前会话的树状分支视图（宽屏下左侧是回合树，右侧实时预览每个回合的内容）。
2. 用 `↑` / `↓` 找到想回退的那个回合，按 `Enter` 即可**从该回合分出一条新分支继续对话**，原分支完整保留，随时可以再切回去对比。
3. **给关键节点打标记**：在树里选中某个重要里程碑回合，按 `Alt+L` 可以给它加文字标签（例如“方案 A 通过单测”），按 `Alt+B` 可以筛选只看带标签的节点。

> **会话分支和文件改动的关系**：在会话树里切换分支只切换**对话历史**，默认不会自动修改你磁盘上的代码文件。如果需要同时把代码文件恢复到某一回合之前的样子，配合下面介绍的**文件恢复快照**即可。

## 三、改乱了代码？用文件恢复快照安全回退（`Alt+R`）

如果不小心让助手把几个文件改乱了，又还没来得及 `git commit`，可以开启内置的**文件恢复快照**：

1. **提前开启**：运行 `/settings`，进入 **`插件` → `工具` → `文件恢复快照`（`File recovery snapshots`）** 并开启。之后每个新回合开始前，omdsh 会自动记录涉及文件的快照。
2. **预览并选择恢复**：双按 `Esc` 打开会话树，选中出问题的那个回合，按 **`Alt+R`**：
- 先勾选要恢复的文件（如果有你在回合之后手动改过的文件，系统会自动标为冲突并跳过，不会盲目覆盖你的心血）；
- 逐个文件预览“回合前”与“回合后”的内容差异；
- 确认后执行恢复，并在对话里输出一份清晰的恢复报告。

> 提示：文件恢复快照仅保存在本机配置目录中，适合作为 `git` 之外的即时“后悔药”，重要里程碑仍建议正常 `git commit`。

## 四、区分容易混淆的几个会话操作

| 操作 | 实际效果 | 什么时候用 |
|---|---|---|
| `/continue` | 接着上一次中断的位置继续生成 | 网络抖动、接口限流或中途被打断，想让模型接着把未说完的话说完。 |
| `/retry` | 带着原来的提问和附件，重新跑一遍上一轮 | 对上一轮回答方向不满意，或者刚换了更强的模型/调高了推理强度想重做一次。 |
| `/compact` | 让模型把早期长对话压缩成精炼摘要，继续留在当前会话 | 状态栏 `Ctx` 占用偏高、开始变黄/红，或对话已经很长想省 token 时。 |
| `/new` | 开一段全新会话（可在发消息前重新选 Agent 预设） | 换了一个完全不相关的新需求，不需要任何旧上下文。 |
| `/clear` | 在当前会话下清空上下文重新开始，屏幕上方留一条分界线保留原终端滚动记录 | 留在当前目录和配置下彻底重来，但想在终端里继续向上翻看刚才的输出。 |

## 五、盯住上下文占用并适时 `/compact`

会话变长后，模型每次请求都要带上历史上下文，既慢又费额度：

1. **看状态栏**：平时留意底部第二行的 `Ctx` 百分比；超过 75% 时会变黄预警，超过 90% 会变红。
2. **查明细（`/context`）**：运行 `/context` 可以看到直观的 5×8 占用网格以及系统提示、工具定义、对话消息三部分的估算占比；点击 **`详情`（`Details`）** 可以看完整 Token 统计和会话信息，或直接点 **`压缩`（`Compact`）**。
3. **执行压缩（`/compact`）**：也可以直接输入 `/compact`，或者附带一句保留重点，例如：

```text
/compact 保留最终确定的 API 接口定义、已修改的文件清单和未解决的 2 个测试失败，其余探索过程精简
```

压缩后历史上下文会大幅瘦身，但早期的细节不会再原样传给模型，因此**在把重要结论写成代码或文档之后再压缩**效果最好。

## 六、导出与分享会话（`/export`）

需要把排查过程发给同事、写进故障复盘文档，或者留档备份时，运行 `/export` 并选择格式：

| 导出格式 | 包含什么 | 适合做什么 |
|---|---|---|
| **Markdown（`.md`）** | 干净的纯文本对话与代码块 | 贴进 PR 说明、Wiki、团队复盘文档。 |
| **HTML（`.html`）** | 自包含的单文件网页，带完整样式与折叠 | 发给没有装 omdsh 的同事直接在浏览器里阅读。 |
| **归档包（`.zip`）** | 完整会话记录、关联子智能体记录及原始图片附件 | 长期留档备份（注意：归档包用于留存与查阅，不支持再导回 omdsh）。 |
