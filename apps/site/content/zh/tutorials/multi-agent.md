# 多智能体协作与 Agent Teams

做大型改动时，把所有排查、编码、写测试都堆在主对话里，既慢又容易迅速塞满上下文。omdsh 提供三种不同层级的“帮手”机制：帮你把独立任务分出去并行干，同时让你随时看得见、管得住。

## 先选对模式：三种协作方式对比

| 协作方式 | 它是什么 | 上下文与状态 | 最适合什么场景 |
|---|---|---|---|
| **内置子智能体**（主助手按需自动委派） | 主助手派生出的轻量助手，分“全新启动 / 继承当前上下文分叉 / 独立进程隔离”三种方式 | 可续跑（能切进去看过程、发追问）；结果汇总回主对话 | 并行调研多个模块、同时写多组互不冲突的单测、隔离跑重量级代码检查。 |
| **Agent Teams（`/team`）** | 开启本会话的**共享任务板**，主助手与多个可续跑子智能体一起认领任务、声明文件修改范围 | 共享同一份任务清单、前置依赖（`blockedBy`）与文件写范围冲突告警 | 涉及前后端/多模块的协作重构，需要明确“谁改哪几个文件、谁等谁先完成”。 |
| **外部子智能体（Codex / Claude Code）** | 通过内置集成把一段完整任务交给本地 Codex 或 Claude Code 执行 | 一次性纯文本任务（无续跑）；登录与默认模型沿用各自的原生配置 | 你已经在本地配置好 Codex 或 Claude Code，希望把某个独立子任务交给它完成并拿回结果。 |

> 如果你不确定该选哪种：**平时直接让主助手并行干活，它会自动选用合适的内置子智能体；只有当多个子智能体需要同时改代码、且要靠任务依赖和文件范围防撞车时，再打开 `/team on`**。

## 场景一：委派子任务、切进去看并实时纠偏

不需要记复杂命令，直接把可并行的任务说清楚即可。例如：

```text
请同时派两个子智能体分别完成两件事，互不干扰：
1. 检查 @src/auth 下所有接口的错误码是否统一；
2. 检查 @src/billing 的 webhook 验签逻辑是否有边界漏洞。
两者完成后把结果汇总成一份修复清单给我。
```

### 如何查看和引导运行中的子智能体

主助手派生出子智能体后，**输入框上方会出现子智能体列表**，实时显示每个子智能体的名称、当前状态（运行中 / 等待 / 已完成）和耗时：

1. **切入子智能体视图**：在列表上按方向键选中并按 `Enter`（或用鼠标直接点击），界面会切换到该子智能体的独立对话记录，就像查看主对话一样清晰。
2. **给它发追问或纠偏**：只要这个子智能体是可续跑的，你可以直接在它的输入框里发送追问，或在它运行时按 `Alt+S` 插话纠偏。
- 注意：子智能体追问支持**文字和图片**，但**不支持附加文件**（如果草稿里有文件附件会被提示拒绝）。
3. **返回主对话**：按 `Esc` 回到主智能体视图，等待它把各路结果汇总起来。

## 场景二：开启 `/team` Agent Teams 协同改代码

当你准备让主助手带着几个子智能体**同时修改不同模块的代码**时，开启 Agent Teams 可以有效防止“两个助手同时改烂同一个文件”：

### 1. 开启团队模式

在输入框运行：

```text
/team on
```

开启后，当前会话树里的主助手和可续跑子智能体都会获得一套共享任务板工具（`team_task_*`）。

### 2. 给一个清晰的协作目标

例如：

```text
用团队任务板把“新增导出历史页面”拆成 3 个任务并行推进：
- 任务 1：后端 API 与类型定义（写入范围 src/server/export/）
- 任务 2：前端列表组件（依赖任务 1，写入范围 src/web/export/）
- 任务 3：端到端测试（依赖任务 1 和 2，写入范围 tests/export/）
请先建好任务和写入范围，再分配子智能体认领执行。
```

### 3. 随时用 `/team` 巡检任务板

任务推进过程中，随时运行 `/team` 打开交互式任务板（也可以运行 `/team status` 直接在对话里输出一份 Markdown 状态总览）：

- **查看状态与归属**：每个任务都会标明 `pending (ready)`（可认领）、`pending (blocked)`（等待前置任务）、`in progress`（进行中）或 `completed`（已完成），以及当前认领者；
- **查看写入范围冲突告警**：如果两个任务声明了重叠的文件写入范围，任务板和任务详情页会醒目标出写范围冲突警告，方便你提前介入调整；
- **查看任务详情**：选中任意任务按 `Enter` 可阅读完整描述、依赖列表和冲突提示；
- **随时关闭**：不再需要任务板时运行 `/team off`（已记录的任务历史会保留，只是后续步骤不再向模型暴露任务板工具）。

## 场景三：启用并委派给 Codex 或 Claude Code

omdsh 随包内置了 Codex 和 Claude Code 两个原生子智能体集成（默认关闭，不会未经允许调用外部工具）：

1. 运行 `/settings`，切到 **`插件`（`Plugins`）→ `子代理`（`Agents`）**（也可以在 `/plugins` 的扩展包列表里进入），选择 `Codex` 或 `Claude Code` 并启用。
2. 在同一菜单里可以查看：
- **安装状态**：检查内置运行环境是否就绪；
- **模型与权限**：模型留空则继承各自的原生配置；权限模式与主会话互相独立（默认较保守：Codex 默认 `never`，Claude Code 默认 `dontAsk`），按需放宽即可。
3. 启用后，只需在对话中明确说“用 Codex 帮我排查这个问题”或“让 Claude Code 审一下这份重构方案”，主助手就会把任务委派出去并把最终结论带回当前对话。

## 使用建议与边界

- **别把简单任务拆得太碎**：子智能体启动本身有成本，两三个文件的小改动让主助手直接做往往更快。
- **控制嵌套深度**：默认最多允许 1 层派生（避免子智能体套娃消耗大量额度）；如需调整并发数、嵌套深度或限制子智能体可用模型，可在 `/settings` 的 **`插件` → `子代理`** 中统一配置。
- **查看全部细节**：关于三种底层运行模式、权限继承与 `cordis.patch.yml` 进阶开关，请参阅[子智能体与团队协作参考](../subagents.md)。
