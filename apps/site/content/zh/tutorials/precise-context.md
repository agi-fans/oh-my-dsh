# 精准上下文与快捷操作

让编程助手干得准、少绕弯的关键，是**一开始就把准确的上下文交到它手里**，同时在查小问题或跑小命令时不打断主对话节奏。这篇教程带你掌握日常最高频的 6 种输入手段。

## 先选对方式：四种提供上下文的手段对比

| 方式 | 实际效果 | 最适合什么场景 |
|---|---|---|
| `@路径` 或 `./路径` | 把准确文件路径插入输入框（高亮显示），由模型按需读取对应文件内容 | **最常用**。指向项目内的源码、配置或测试文件，不白白占满上下文。 |
| `/attach <文件路径>` | 显式把文件作为附件绑定到本条消息中 | 需要把当前目录外的参考文件、日志或整份规格文档直接附带发给模型。 |
| `@会话`（输入 `@` 后选会话） | 把某条历史会话的只读摘要快照插入上下文，不会切换或修改原会话 | 在新会话里续接昨天的排查结论，或把另一个分支的结论带过来参考。 |
| 粘贴或附加图片 | 把截图/设计稿编码后随消息发给多模态模型 | 报错截图、UI 排版走样、终端界面对比、架构图。 |

## 1. 用 `@` 精准指向文件和历史会话

在输入框中键入 `@` 后直接输入片段（支持模糊匹配，例如 `@auth`、`@user.spec`），下方会自动弹出候选列表：

- 按 `↑` / `↓` 移动，`Tab` 或 `Enter` 选中插入；
- 输入 `./` 或 `~/` 也能触发路径补全，方便引用相对路径或用户目录下的文件。

一个高效提问的结构通常是：**目标 + 指向具体文件 + 约束或验证方式**。对比这两种写法：

- 模糊写法：`登录接口好像有问题，帮我看一下。`（助手得先全局搜一遍项目，慢且容易改错地方）
- 精准写法：

```text
@src/auth/session.ts @src/auth/session.spec.ts
检查 token 过期刷新时是否存在并发竞态；不要改外部接口签名，先给出复现用例再修复。
```

### 引用历史会话

当你想把之前排查过的问题带到新任务里时，在输入框键入 `@` 并输入关键词，选中对应的历史会话条目即可。例如：

```text
参考 @支付超时排查 里的结论，帮我检查 @src/orders/checkout.ts 是否有同样的重试超时风险。
```

这样做会把该历史会话的只读快照附在当前问题中，既保留背景，又不会把当前新会话污染成几百轮的长历史。

## 2. 用 `/attach` 显式附加文件

如果文件在项目外，或者你想确保文件作为显式附件随消息发送，直接运行：

```text
/attach ../specs/api-v2.md
```

你也可以连续附加多个文件，再输入你的提问一起发送。不带参数直接运行 `/attach`，可以查看并预览当前已附加的图片附件。

## 3. 粘贴截图与预览图片

> **先确认模型支持视觉输入**：目前多数默认文本模型不支持图片；如果使用 DeepSeek，请先通过 `/model` 切换到支持图片的模型（例如 `deepseek-flash`），否则发送带图消息时模型会拒绝请求。

附加图片有三种方式：

- **直接粘贴剪贴板截图**：macOS 按 `Cmd+V`（或 `Ctrl+V`），Linux 按 `Ctrl+V`，Windows / WSL 按 `Ctrl+Alt+V`；
- **把图片文件直接拖进终端窗口**，或输入 `/attach /path/to/screenshot.png`。

粘贴后输入框里会出现类似 `[Image #1]` 的紧凑占位符：

- 按 `Alt+M` 可以在终端内预览草稿里的图片（在 Kitty、Ghostty、WezTerm、iTerm2 等终端支持内联显示，也可点击 `打开` 调用系统看图软件）；
- 在图片占位符上按一次 `Backspace` 即可整张移除。
- **大小提示**：单张图片最大支持 20 MiB，超大分辨率图片在发送前会自动等比压缩以控制上下文开销。详细限制见[命令参考](../commands.md)。

## 4. 写长需求与保护大段粘贴

- **多行输入**：按 `Shift+Enter` 或 `Ctrl+J` 换行；需要写一大段设计说明时，按 `Ctrl+X` 在外部编辑器（如 VS Code、Neovim）里写完保存退出，内容会自动回到输入框。
- **暂存未写完的草稿**：写到一半想先问另一件事？按 `Ctrl+S` 把当前草稿暂存起来，等会儿再按 `Ctrl+S` 取回。
- **大段粘贴折叠**：粘贴多行代码或超长日志时，输入框会自动折叠成 `[Pasted N lines]` 占位块，避免刷屏。按 `Alt+I` 可展开直接编辑；如果你刚好粘贴了一条以 `/` 开头的日志或路径，omdsh 会保护它不被误当成斜杠命令执行。

## 5. 用 `!命令` 在输入框里直接跑 Shell

写代码时经常想顺手看一眼 `git status`、跑一条测试或查一下端口，不需要切窗口，也不用麻烦模型替你执行：

- 在空输入框里直接输入 **`!`**（输入框边框会变成绿色），然后输入命令，例如：

```text
!git status -sb
```

- **`!命令`（单个感叹号）**：结果直接显示在终端里给你看，**不会进入模型上下文**，零 token 消耗；
- **`!!命令`（两个感叹号）**：命令跑完后，**自动把输出分享给模型**，适合“我自己跑完这条报错命令，直接让助手看结果分析”。
- 这个快捷 Shell 是**持久会话**，你执行 `!cd packages/api` 后的目录变化会在下一条 `!` 命令里保持生效；命令跑太久时按 `Ctrl+C` 或空输入框按 `Esc` 即可中止。

## 6. 用 `/btw` 旁路查一个小问题，不污染主对话

正在专注重构一个复杂模块时，突然想问个顺手的小问题（比如“Node 22 里 `AbortSignal.any` 怎么用？”或“刚才提到的那个字段在 schema 里允许为空吗？”），直接发进主对话既打断节奏又浪费上下文。

这时用 `/btw`：

```text
/btw 刚才改的 OrderStatus 枚举在数据库迁移脚本里有没有硬编码？
```

- `/btw` 会基于当前已提交的对话上下文发起一次**只读旁路提问**，不修改文件，也不把问答塞进后续主对话上下文；
- 回答会在底部以流式浮层呈现，看完按 `Esc` 收起，主对话保持干净；
- 之后如果想回看或复制，在对话里找到折叠的 `/btw` 行按 `Ctrl+O` 展开，或用 `/copy` 复制。
