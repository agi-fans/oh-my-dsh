# 性能与边界

omdsh 从架构上把终端响应速度放在优先位置：会话日志线性回放、已完成区块缓存、流式内容合并帧与行级差分输出，让几千轮长会话和长代码块预览依然保持顺滑。

## 一、日常使用中的实际保护上限

遇到超大内容时，omdsh 会用清晰的内置上限保护终端不卡顿、上下文不被撑爆：

| 场景 | 内置保护与实际表现 |
|---|---|
| **长会话回放（数千至上万回合）** | 采用线性回放器与按区块布局缓存；滚动和打字不会重排历史回合。建议在状态栏 `Ctx` 超过 75% 时配合 `/compact` 精简模型上下文。 |
| **大文件与 Diff 预览（`/diff`）** | 文本初次加载 **128 KiB**，按 `L`（`Load more`）每次翻倍至最高 **4 MiB**；更大文件或二进制文件按 `O` 用系统默认应用打开。不折行模式下仅按需切出当前可见行。 |
| **单条超长流式回复** | 密集流式输出在 8 ms 帧窗口内合并绘制，并在流式追加时复用已稳定的 Markdown 前缀块；除非出现引用链接定义或渲染宽度变化，约十二万字符的富文本回复也能保持在单帧预算内。 |
| **文件恢复快照（`Alt+R`）** | 单文件超 **128 MiB**、快照超 **1 GiB** 或工作区超 **10,000** 个条目时自动跳过捕获，避免拖慢正常回合。 |
| **图片附件与归档导出** | 发送单图上限 **20 MiB**（超大分辨率自动等比压缩）；预览解码上限 32 MiB / 4000 万像素；`/export archive` 未压缩上限 **64 MiB**。 |
| **tmux / 复用器缩放** | 窗口连续 resize 时合并突发重绘并保留宿主滚动历史；如重连后显示错位，按 `Alt+L` 即刻重绘实时视口。 |

## 二、为什么大项目里不容易卡

1. **线性时间会话回放**：恢复持久化日志时直接按线性顺序构建区块，并维护 `callId → 区块索引` 映射，避免随回合数增加出现二次方卡顿。
2. **直接消费计量投影**：Token、上下文占比与会话统计直接读取运行时已维护的投影数据，不在每次流式更新时重扫历史日志。
3. **区块与流式缓存**：已完成的 Markdown、工具卡片、吸顶标题以及流式输出中已稳定的 Markdown 前缀都会按区块与宽度缓存，在流式追加、编辑草稿、播放微光动画或翻页时直接复用。
4. **行级差分输出**：每帧只把真正变化的可见行写入终端，不清空重画整屏，大幅减少终端和 SSH 链路上的输出字节量。

## 三、实测基准数据（2026-11-06）

以下数据在 **Apple M5 Pro（48 GiB 内存，macOS，Node.js v24.18.0）** 上测得，衡量 TUI 本地 CPU 处理耗时（不含网络、磁盘 I/O 与终端 GPU 绘制；单位：毫秒）：

| 工作负载 | 优化前 p50 | 优化后 p50 | 优化后 p95 | 样本数 |
|---|---:|---:|---:|---:|
| 109,500 字符 Markdown 预览滚动（160×50） | 21.986 | **0.383** | 0.454 | 20 |
| 10,000 行代码横移（读取 45 行可见内容） | 52.618 | **0.212** | 0.216 | 10 |
| 回放 10,000 回合（含起止生命周期事件） | 453.203 | **2.567** | 5.651 | 7 |
| 回放 20,000 回合（含起止生命周期事件） | 2074.193 | **8.442** | 8.699 | 7 |
| 10,000 字符富文本流式帧（80×50） | 3.123 | **1.903** | 2.171 | 15 |
| 50,000 字符富文本流式帧（80×50） | 16.095 | **9.017** | 11.167 | 15 |
| 120,000 字符富文本流式帧（80×50） | 40.064 | **21.973** | 23.522 | 15 |

同机真实 PTY 交互采样（构建产物 + 本地模拟模型）：冷启动至状态栏就绪中位数 **697.4 ms**（RSS 约 310 MiB），输入按键响应 **1.08 ms**，打开 `/help` **4.20 ms**，打开 `/tools` **3.32 ms**，回复完成后空闲 5 秒 CPU 增量约 0.02 s。

## 四、在本地复现基准测试

克隆仓库后可直接运行内置基准脚本（源码位于 [`scripts/benchmark-tui.mts`](https://github.com/agi-fans/oh-my-dsh/blob/main/scripts/benchmark-tui.mts)）：

```sh
pnpm install
pnpm benchmark:tui
```

该脚本同时输出每次渲染的 CPU 耗时、终端写入次数与 ANSI 输出字节量，方便在改动渲染或回放逻辑前后对比是否存在复杂度或输出量回退。
