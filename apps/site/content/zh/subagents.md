# 子智能体与团队协作

想按真实场景一步步上手请先看[多智能体协作与 Agent Teams 教程](tutorials/multi-agent.md)。本页汇总内置子智能体、Agent Teams、外部子智能体集成和进阶配置的完整行为规范。

## 一、内置子智能体的三种运行方式

主助手在委派任务时会根据需要选择三种不同通道：

| 工具 | 运行方式 | 上下文继承 | 典型用途 |
|---|---|---|---|
| **`subagent`** | 同进程、全新上下文 | 不继承父对话历史 | 并行做独立代码调研、模块检查或写独立测试 |
| **`subagent_fork`** | 同进程、从当前对话分叉 | 继承父会话已提交上下文与模型路由 | 顺着刚刚排查出的背景深入做某一路专项任务 |
| **`subagent_isolated`** | 独立子进程隔离运行 | 独立隔离环境（需要 `PATH` 上有支持 `acp` 配置的 `dsh`） | 重量级、需要进程级隔离的自包含任务 |

### 查看、追问与引导子智能体

- **子智能体列表**：只要当前会话产生过子智能体（包括恢复会话后尚未加载的早期子智能体），输入框上方就会显示子智能体列表，按状态、名称与耗时实时更新。
- **切入与返回**：在空输入框按 **`↓`**（或鼠标点击）进入列表，按 `Enter` 打开选中子智能体的完整对话记录，按 `Esc` 返回主会话。
- **发追问与插话**：在可续跑的子智能体视图中，你可以像主对话一样直接发送追问，或在其运行中按 `Alt+S` 插话纠偏。
- **附件限制**：子智能体追问**仅支持文字和图片，不支持文件附件**（草稿包含文件附件时会被拒绝并提示）。
- **权限与审批**：子智能体触发审批时，弹窗会标明具体来自哪个子智能体，多个并发请求按顺序逐一呈现；切换主会话会取消原会话及其本地子智能体的待处理审批。

## 二、Agent Teams（`/team` 共享任务板）

当多个可续跑子智能体需要**协作修改同一仓库的不同模块**时，使用 `/team` 协调任务分工与防文件冲突：

- **开启与关闭**：`/team on` 开启当前会话树的团队模式，向主助手及可续跑子智能体开放 `team_task_*` 工具；`/team off` 隐藏工具并保留已记录的任务。
- **查看与巡检**：
- `/team`：打开交互式任务板，支持快速筛选、刷新、切换开关，以及选中任意任务按 `Enter` 阅读完整描述、前置依赖（`blockedBy`）与写范围冲突告警；
- `/team status`：直接在对话里打印 Markdown 格式的任务板状态总览（适合纯文本/非交互环境）；
- 在子智能体视图内执行 `/team` 会自动解析并操作根会话的任务板。
- **任务并发保护**：任务板基于乐观并发控制（Compare-and-Set），单棵会话树最多支持 **256** 项任务，每个任务支持声明 **`writeScopes`**（允许写入的文件或目录范围）——当多个任务声明的写范围出现重叠时，任务板会显式给出写范围冲突警告。

## 三、外部子智能体集成：Codex 与 Claude Code

omdsh 随包内置了 **Codex**（`@deepseek-ai/dsh-subagent-codex`）和 **Claude Code**（`@deepseek-ai/dsh-subagent-claude-code`）两个原生子智能体集成（默认关闭）：

- **启用与配置路径**：前往 `/settings` → **`插件` → `子代理`**（或 `/plugins` → `插件包` → `集成设置`）。
- **核心行为特点**：
- 使用各自随包固定的平台运行时（不依赖系统 `PATH` 上临时装的版本）；
- 登录凭据与默认模型直接沿用你本机的原生 Codex / Claude Code 配置（omdsh 不读取也不存储它们的登录凭据）；
- 子代理的权限模式与主会话互相独立，**默认值保守**（**Codex 默认 `never`，Claude Code 默认 `dontAsk`**），按需放宽后再允许它们改文件；
- 均为**一次性纯文本任务**：只返回最终结论给主助手，不支持中途续跑，也不产生本地子会话记录；
- 出于安全原因，默认会清除父进程中的凭据类环境变量，不会把主会话的 API Key 隐式传给外部子代理。

## 四、限制与进阶配置

### 1. 深度、并发与模型白名单

前往 `/settings` → **`插件` → `子代理` → `通用设置`** 配置：

- **最大派生深度（`maxDepth`）**：默认 `1`（主代理为 `0`，直接子代理为 `1`；若某个工具自身配置了更严格的深度上限，以工具自身为准）。
- **最大并发数**：限制同一会话树内同时运行的本地与外部子代理总数（不含主代理）；调小上限只限制新派生的任务，不会强杀正在运行的子代理。
- **允许的子代理模型**：默认关闭；开启后可勾选白名单模型，仅作用于新会话（`subagent_fork` 仍继承父会话模型）。

### 2. 编排工具与可选高级开关

- **`workflow_run`**：在 `Standard` 预设下可用，用于执行多步确定性工作流（`PTC` 预设刻意隐藏它以避免与 `run_code` 编排冲突）。
- **开启默认关闭的 `ralph` 循环**：直接在 `/settings` → **`插件` → `可选功能` → `Ralph 循环`** 打开即可。
- **开启默认关闭的 `interrupt_agent` 工具**：如确需允许模型主动中断子代理，可在 `$OMDSH_HOME/profiles/omdsh/cordis.patch.yml` 中取消禁用：

```yaml
- id: tool-interrupt-agent
  disabled: false
```

修改 `cordis.patch.yml` 后重启 `omdsh` 生效。
